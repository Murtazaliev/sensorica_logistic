# Project brief — Система доставки полуфабрикатов

## Проблема

Цех производит полуфабрикаты и доставляет их по точкам (магазины, кафе). Сейчас заказы живут в amoCRM, а доставка планируется вручную. Нет единого статуса «где заказ», фотофиксации, учёта тары, офлайн-работы курьеров и прозрачной аналитики.

## Цель

Единая система: amoCRM → диспетчер → курьер (офлайн) → точка → аналитика, с возвратом статусов в CRM.

## Пользователи (роли)

| Роль | Код | Где работает |
|---|---|---|
| Менеджер продаж | `SalesManager` | amoCRM + мини-панель `/manager` |
| Диспетчер | `Dispatcher` | Blazor Web |
| Курьер | `Courier` | .NET MAUI, offline-first |
| Менеджер точки | `PointManager` | PWA |
| Администратор | `Admin` | Blazor Web |
| Руководитель | `Head` | Blazor Web, read-only + управление точками |

## Ключевые ограничения

- Отправка стартует в **10:00**; заказы «на сегодня» после 10:00 автоматически переносятся на следующий рабочий день.
- Маршруты на сегодня блокируются в 10:00.
- Курьер работает в офлайн-зонах — синхронизация обязательна.
- Мультитенантность (несколько цехов в одной системе).

## Scope MVP

**Входит:**
- приём заказов (мок amoCRM), точки, маршруты, статусная модель;
- диспетчер: входящие, планирование вручную, трекинг, проблемы;
- курьер: маршрут, доставка, фото/подпись, офлайн-синк, тара;
- точка: подтверждение приёмки;
- админ: справочники, пользователи, настройки времени;
- уведомления InApp + Push.

**Не входит в MVP:**
- VRP-автомаршрутизация (только ручное планирование + карта);
- ЭДО;
- финансовые выплаты курьерам (только выгрузка);
- дашборд руководителя (кроме базовых KPI);
- модерация точек (выключена по умолчанию);
- Telegram/Email-каналы.

## Метрики успеха

- 100% заказов имеют прозрачный статус.
- 0 потерянных доставок при офлайне.
- Сокращение времени планирования маршрута.
- Доля доставок в срок ≥ 95%.
