# ADR-0015. Жизненный цикл маршрута у курьера

- Дата: 2026-10-27
- Статус: Accepted

## Контекст

Курьер уже видел подтверждённый маршрут на `/my-routes`, но не мог его принять, начать или отметить остановки. Заказы не меняли статус, route-snapshot оставался неизменным. Нужен минимальный рабочий цикл доставки.

## Решение

1. **Приём и старт.** У `Route` добавлен `AcceptedAt`. `AcceptAsync` фиксирует принятие подтверждённого маршрута; `StartAsync` переводит маршрут в `InProgress` (и при необходимости фиксирует принятие).
2. **Статусы остановок.** `RoutePoint.Status`: `Pending` → `Arrived` (фиксируется `ActualArrivalAt`) → `Delivered`/`Problem` (фиксируется `CompletedAt`). Действия доступны только владельцу-курьеру и только для маршрута `InProgress`.
3. **Статусы заказов.** При старте заказы переводятся в `InTransit`, при доставке — в `Delivered`, при проблеме — в `Problem`. Каждый переход пишет `OrderStatusHistory` (комментарий, `IsSystemAction=false`), увеличивает `Order.Version` и добавляет `SYNC_CHANGE(Order)`.
4. **Изменение маршрута.** После каждого действия пишется route-snapshot в change feed; при доставке/проблеме последней остановки маршрут становится `Completed`. Проблемная остановка не блокирует завершение — важна фиксация результата.
5. **UI `/my-routes`.** Кнопки «Принять маршрут», «Начать маршрут», «Я на точке», «Доставлено», «Проблема» (с комментарием). Отображаются статус остановки, статус заказа, прогресс «выполнено N из M», плановые окна и карта.
6. **Без отдельного API.[^1]** Действия выполняются через `RouteService` в Blazor-хосте; для офлайн-клиента позже появятся идемпотентные sync-операции и HTTP-эндпоинты.

## Последствия

- Плюсы: курьер может пройти маршрут от принятия до доставки; статусы заказов и маршрута синхронизируются; диспетчер видит прогресс после обновления.
- Минусы: нет офлайн-очереди и идемпотентных client operation id для действий; нет фото/подписи/QR, ETA и переназначения; действия нельзя выполнить из MAUI до появления API; подтверждение маршрута по-прежнему не меняет статусы заказов (это делает старт).
- Проблема завершает маршрут; полноценный разбор проблем — следующий этап.

## Проверка

- 2 новых теста: полный цикл accept → start → arrive → deliver (маршрут `Completed`, заказы `Delivered`) и проблема (заказ `Problem`, маршрут `Completed`). Всего **34/34** на момент ADR; после отображения курьера в заказах — **35/35**.
- На запущенном приложении `/my-routes?date=завтра` показывает «Принять маршрут» и «Начать маршрут», карту и остановки.
