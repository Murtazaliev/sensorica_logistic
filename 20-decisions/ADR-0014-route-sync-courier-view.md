# ADR-0014. Маршрут в синке и веб-экран курьера

- Дата: 2026-10-27
- Статус: Accepted

## Контекст

Диспетчер собирал и подтверждал маршрут, но курьер его не видел: маршрут жил только в БД и не попадал в change feed. Для офлайн-клиента (MAUI/PWA) маршрут должен приходить через тот же delta pull, что и заказы/точки. Для проверки сценария нужен и веб-экран курьера.

## Решение

1. **Route в change feed.** `SyncEntityType.Route`; `RouteSyncSnapshot` содержит заголовок маршрута (курьер, дата, статус, точки, вес, дистанция/время), геометрию и остановки с плановыми окнами. `SyncChangeFactory.ForRoute` строит payload.
2. **Запись изменений.** `RouteService` добавляет `SYNC_CHANGE` (`Upsert`) при сохранении остановок и при подтверждении. Черновики тоже пишутся; клиент фильтрует по статусу.
3. **Экран курьера `/my-routes`.** Доступен роли `Courier`; профиль курьера находится по `AppUser.Id` → `Courier.UserId`. Показывает сегодня/завтра (или `?date=YYYY-MM-DD`) только `Confirmed`/`InProgress`/`Completed`; черновики и отменённые скрыты.
4. **Карта и остановки.** MapGL: цех, дорожная геометрия, пронумерованные остановки; список с адресом, плановым окном, весом и статусом заказа. Только чтение — назначение делает диспетчер.
5. **Навигация.** Курьер после входа попадает на `/my-routes`; в сайдбаре «Мои маршруты». `PointManager`/`SalesManager` остаются на `/welcome`.

## Последствия

- Плюсы: маршрут доступен курьеру на веб-экране и через sync pull; MAUI/PWA сможет кешировать снимок; диспетчер видит, что маршрут назначен.
- Минусы: веб-экран курьера не офлайн; нет приёма/отклонения маршрута и навигации; изменение статусов заказов при подтверждении маршрута не реализовано; route-снапшоты черновиков увеличивают change feed.
- Геометрия в снапшоте может быть большой (сотни точек); для мобильного клиента нужна компакция/сжатие.

## Проверка

- Курьер входит и попадает на `/my-routes`; `/my-routes?date=завтра` отдаёт 200, остановки и карту.
- Подтверждение маршрута добавляет два `Route`-изменения (остановки + подтверждение); payload содержит `stops`.
- Тесты: **32/32** (профиль курьера по user id, route-snapshot при остановках/подтверждении).

## Что дальше

- MAUI/PWA курьера: pull маршрута, локальный кеш, офлайн-статусы, навигация.
- Приём/отклонение маршрута, «Я не смогу», переназначение.
- Смена статусов заказов и ETA по остановкам; сжатие геометрии в снапшоте.
