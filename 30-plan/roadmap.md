# Roadmap

> Оценки для команды из 3 разработчиков. Соло — умножать примерно на 2, команда из 5 — делить на ~1,4.

## Принцип

Сначала — два риск-спайка (офлайн-синк, приём заказов через мок), потом домен, потом UI. Не начинать с экранов.

> Спайки выполнены: приём заказов через мок (ADR-0003) и офлайн-синк (ADR-0007). См. `current-state.md`.

## Итоговые сроки

| Вариант | MVP (без 7–8, 11) | Полная версия до пилота |
|---|---|---|
| Соло | 5–7 мес | 18–24 мес |
| 3 разработчика | 2,5–3,5 мес | 9–12 мес |
| 5 разработчиков | 2–2,5 мес | 6–8 мес |

Трудозатраты: MVP ~1200–1600 ч, полная версия ~3500–4500 ч (без дизайна/DevOps).

## Что режем в MVP

- VRP → ручное планирование + карта.
- ЭДО, выплаты → только экспорт.
- Дашборд Head → 4–5 KPI без тепловой карты.
- Модерация точек → выключена.
- Telegram/Email → только InApp + Push.

## Риски

1. **Офлайн-синк** — главный риск переписывания. Спайк выполнен (ADR-0007), риск снижен; остались ретенция, device presence и полный набор операций.
2. **amoCRM** — чужая система: задержки, дубли, смена API. Outbox + мониторинг.
3. **Гонка в 10:00** — cutoff/блокировка/старт в одну минуту. Тесты с управляемыми часами.
4. **Подпись/фото** — юридическая значимость, ретенция, `FILE`.
5. **Пилот** — реальные офлайн-зоны выявят непредусмотренное. Закладывать 2–4 недели.
