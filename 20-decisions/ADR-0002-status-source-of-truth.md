# ADR-0002. Источник истины по статусу заказа

- Дата: 2026-10-27
- Статус: Accepted

## Контекст

`Order.Status`, `Route.Status` и `RoutePoint.Status` пересекаются. Без правила источник истины они расходятся: заказ «В пути», а точка маршрута «Pending».

## Решение

- Оперативный статус хранится в `RoutePoint.Status`.
- `Order.Status` меняется только доменным сервисом в той же транзакции, что и `RoutePoint.Status`.
- Каждый переход пишется в `OrderStatusHistory` (с `IsSystemAction` и `CorrelationId`).
- `Route.Status` — производный агрегат: `InProgress` при первой точке `Arrived/InTransit`, `Completed` когда все точки терминальны.
- Прямое редактирование `Order.Status` из UI запрещено; только через доменные команды.

## Последствия

- Плюс: нет рассинхрона, единая точка изменения.
- Минус: все изменения статуса проходят через сервис, UI не пишет напрямую.
- Нужно: покрыть переходами тестами (state machine) и запретить прямые UPDATE в репозиториях.
